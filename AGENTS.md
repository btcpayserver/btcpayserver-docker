# Agent Instructions

## Generated Image Documentation

`contrib/build-all-images.sh` and the image table in the root `README.md` are
generated by `contrib/DockerFileBuildHelper`. Do not edit either generated
section manually.

Do not run `contrib/build-all-images.sh`. It clones source repositories and
builds every referenced image. Only regenerate it and validate its shell syntax
with `bash -n` as described below.

When changing an image reference in
`docker-compose-generator/docker-fragments/`, regenerate both artifacts from
the helper directory:

```bash
cd contrib/DockerFileBuildHelper
./update-repo.sh
```

The helper discovers images from the compose fragments, maps each image to its
source repository, ref, and architecture-specific Dockerfiles in `Program.cs`,
validates that the mapped Dockerfile URLs exist, then writes both outputs. If it
reports a missing image mapping, update `GetDockerInfo` when a verified source
build is available. If an image intentionally cannot or should not be built
from source, make the helper skip it rather than inventing a mapping or editing
the generated output.

A broken Dockerfile link often means that a published image does not yet have a
matching source tag. Verify the image's actual build provenance before changing
the mapping. When necessary, pin a verified immutable source commit temporarily;
replace it with the matching source tag only after that tag is accessible.

Run `./update-repo.sh` twice and confirm the second run makes no changes. Then
validate the helper and generated script:

```bash
dotnet build --no-restore -c Release
bash -n ../build-all-images.sh
git diff --check
```

Review the generated diff with the source fragment change. Do not assume a
successful generation proves that the selected source ref produced the
published image; link validation checks availability, not provenance.
